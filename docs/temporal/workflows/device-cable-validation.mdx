Validates network connections for a specific device by checking physical and logical connectivity.

## User Interface

### Form Inputs

Users interact with a simple two-step form:

| Field | Description | Selection Type | Required |
| :---- | :---------- | :------------- | :------- |
| **Site** | Choose the site containing the device | Single dropdown from available sites | Yes |
| **Device** | Select the specific device to validate | Single dropdown from devices in selected site | Yes |

## Workflow Execution

### Execution Stages

1. Validate hostname
1. Get device intended neighbors
1. Get device actual neighbors
1. Validate device neighbors

### Cable-status persistence

The report remains visible while the configured DCIM provider saves cable statuses.
The workflow passes each device's full set of changes to one persistence activity,
with a one-hour timeout per attempt and up to three attempts in total.
The provider chooses its write strategy; see
[Nautobot cable-status persistence](../../nautobot/nautobot-integration.mdx#cable-status-persistence)
for the bundled plugin's limits.

A transient persistence failure in a standalone device run leaves the validation
stage available for manual **Retry**. Retrying reuses the collected ARP, MAC, and
LLDP data and regenerates the report before attempting persistence again.
Report-generation failures fail the run promptly. Site child workflows return
their pending changes to the parent, which persists them after generating the
site report. Closed failed workflows require another run.

## Report

The report and CSV export include **Intended Interface Label** from the DCIM
and **LLDP Port Description** from the observed neighbor, alongside the intended
and actual interface names. Missing metadata appears as `--` in the table.
See [Interpreting the report](../../user-guides/cable-validation/index.mdx#interpreting-the-report)
for a hyper-reach port-metadata mismatch example.
