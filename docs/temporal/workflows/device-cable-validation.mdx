Validates network connections for a specific device by checking physical and logical connectivity.

## User Interface

### Form Inputs

Users interact with a simple two-step form:

| Field | Description | Selection Type | Required |
| :---- | :---------- | :------------- | :------- |
| **Site** | Choose the site containing the device | Single dropdown from available sites | Yes |
| **Device** | Select the specific device to validate | Single dropdown from devices in selected site | Yes |

## Workflow Execution

### Execution Stages

1. Validate hostname
1. Get device intended neighbors
1. Get device actual neighbors
1. Validate device neighbors

### Cable-status persistence

Cable-status persistence runs at most two interface updates concurrently per
device activity. New workflow runs save at most 25 interfaces per activity, with
a 15-minute deadline and activity retries scoped to each batch. The Nautobot
provider shares one paginated lookup filtered to the batch's interface names.
Malformed records do not block updates for valid interface matches; unresolved
targets still report invalid data rather than being silently skipped.
REST reads retry transient connection failures, timeouts,
and HTTP 502/503/504 once with jittered backoff; writes are not automatically
repeated by the HTTP client. TLS certificate and fingerprint failures are not retried.

For new standalone device runs, a transient persistence failure leaves the validation
stage available for manual Retry. Retrying that stage reuses the collected
ARP, MAC, and LLDP data and regenerates the report before retrying persistence.
The report remains visible while cable statuses are saved. Existing histories
keep their previous activity schedule and failure behavior for replay compatibility.
Report-generation failures, including in site child workflows, fail promptly; closed failed
workflows require a new run.

## Report

The report and CSV export include **Intended Interface Label** from the DCIM
and **LLDP Port Description** from the observed neighbor, alongside the intended
and actual interface names. Missing metadata appears as `--` in the table.
See [Interpreting the report](../../user-guides/cable-validation/index.mdx#interpreting-the-report)
for a hyper-reach port-metadata mismatch example.
