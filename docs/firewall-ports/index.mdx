Firewalls, security groups, and ACLs between the device network and Config
Manager must permit both device-initiated provisioning traffic and
Config Manager-initiated management traffic. The exact device-facing bootstrap
port depends on the selected transport and platform.

| Protocol / Port | Direction | Purpose |
| --- | --- | --- |
| UDP 67 | Bidirectional (DHCP relay ↔ Config Manager) | Relayed DHCP requests and server responses (`DISCOVER` / `REQUEST` / `OFFER` / `ACK`) |
| TCP 80 | Device → Config Manager | Default private-network HTTP bootstrap-script and firmware downloads |
| TCP 443 | Device → Config Manager | Optional direct ZTP LoadBalancer HTTPS listener for bootstrap and HTTP-compatible downloads |
| TCP 2222 | Device → Config Manager | Default encrypted ZTP SFTP transport for rendered configuration, command files, and certificates |
| TCP 443 | Config Manager cluster → managed device or BMC | Standard HTTPS management APIs, including NVOS, Arista eAPI, and Redfish where those platforms or workflows are used |
| TCP 8765 | Config Manager cluster → Cumulus Linux device | Cumulus NVUE REST API used by deployment, validation, reprovisioning, backup, certificate rotation, and other lifecycle workflows |
| UDP/TCP 53 | Device → DNS resolver | DNS resolution when ZTP/DHCP targets are referenced by hostname (e.g. `ztp.<hostname>`, `dhcp.<hostname>`) |

For Cumulus certificate rotation, both directions are required: the Temporal
worker invokes NVUE on TCP 8765, then the switch retrieves the replacement
certificate from the ZTP SFTP service on TCP 2222.
